# Retro Checklist

Run after each application generated AND after each interview.

## After application

- [ ] Did any bullet feel weak or vague when assembling this variant?
  → If yes: add to promotion-queue.md with note "strengthen for [archetype]"
- [ ] Did any JD theme lack a matching bullet in master-cv.md?
  → If yes: add to promotion-queue.md with note "gap: [theme]"
- [ ] Were any metrics used that are not yet confirmed in facts.md?
  → If yes: ask user to confirm, then update facts.md
- [ ] Did the two-page fit require any cuts?
  → If yes: were cut bullets added to Bench in master-cv.md?
- [ ] Are there bullets in the Bench that should be promoted to active?
  → Flag candidates in promotion-queue.md

## After interview

- [ ] Did any question reveal a gap in how a bullet is framed?
  → Add to promotion-queue.md with note "reframe for interview defensibility"
- [ ] Did any bullet land particularly well?
  → Add to promotion-queue.md with note "promote: strong in [archetype] interviews"
- [ ] Were there topics covered in the interview not reflected in master-cv.md?
  → Discuss with user — may need new bullets (user to provide specifics for facts.md)
- [ ] Update tracking/applications-log.md with new status and last-update date

## Promotion decision rule

Do NOT merge candidates into master-cv.md automatically. Batch and review with user.
Approval required before any bullet moves from promotion-queue to master-cv.md.
